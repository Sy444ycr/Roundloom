# Roundloom 里程碑与验收计划

版本：v0.1 · 待评审
适用阶段：文档设计
关联文档：[产品需求](01-product-requirements.md)、[Agent 接入规范](03-agent-integration.md)

本计划用于判断每个阶段交付了什么、证据是否充分，以及何时可以进入下一阶段。以下内容都是拟定的验收条件，目前没有开展真实 Agent 集成或测试，也没有可报告的通过率、性能或成本结果。项目名已确定为 Roundloom；首个发布版本覆盖到哪个里程碑、开发工作量与付费模型预算仍待决定。

## 1. 分阶段交付

| 阶段 | 交付目标 | 阶段出口 |
| --- | --- | --- |
| D0 文档评审（当前） | 明确产品边界、接入契约、状态语义和验收口径 | 需求与建议分清；重要分歧有决策记录；用户明确提出进入实现阶段 |
| M1 核心流程验证 | 实现群聊、成员、任务和事件的最小流程，使用模拟适配器覆盖正常与异常状态 | 可演示定向派单、任务线程、取消和重连；所有模拟成员及结果明确标注 |
| M2 单个真实连接 | 接通一个真实 Agent，完成会话创建、输入、事件接收和产物展示 | 在独立测试项目中完成任务，保留真实运行证据；支持能力与未支持能力均有记录 |
| M3 异构成员协作 | 两个不同实现的 Agent 在同一任务线程中异步求助与回复 | 原成员能在收到回复后继续工作；等待同伴不会阻塞用户控制；交流具有停止条件 |
| M4 开放接入验证 | 使用新增配置或适配器接入此前未覆盖的 Agent | 群聊与任务核心无需增加厂商分支；完成对应契约检查，更新版本与能力兼容记录 |

以上是依赖顺序，不是时间承诺。M1 的模拟结果只能证明平台流程；M2 的单个连接成功不能直接作为其他 Agent 或其他版本兼容的证据。首批 Agent 名单和优先级在文档评审中确定。

## 2. 核心验收条件

需求编号以产品需求文档为准，编号变更时同步更新此表。

| 验收编号 | 对应需求 | 场景与可观察结果 |
| --- | --- | --- |
| AC-01 | FR-01 动态接入与多实例 | 注册新连接后可加入群聊并进入成员选择列表。同一种 Agent 可创建两个成员，具有不同成员 ID 和独立会话；显示名称不参与路由判断。接入能力和验证状态可查看。 |
| AC-02 | FR-02 群消息与定向路由 | 用户选择一个或多个明确接收成员后发送消息，只有这些成员进入执行队列。引用消息保留关联；其他成员可读取群记录，但不会因可见消息自动启动。同一请求在平台内部重复提交时，返回原记录且不重复调度。 |
| AC-03 | FR-03 任务分配 | 显式分配任务生成原始群消息和关联任务，记录负责人、要求及验收条件。普通讨论保持为消息；任务的排队、执行和等待状态可追溯。 |
| AC-04 | FR-04 异步同伴求助 | A 向 B 发起有请求 ID 的求助，结束当前一轮并保存待答状态；B 的回复关联原任务，调度 A 的下一轮。超时、重复回复和过期回复有明确处理，不产生无限互相唤醒。 |
| AC-05 | FR-05 执行事件与恢复 | 流式消息、执行事件和状态更新归属正确。客户端重连后可补齐平台已持久化的记录；原生执行恢复取决于适配器能力。历史重放不会重新执行任务或重复追加内容。 |
| AC-06 | FR-06 执行控制与等待 | 暂停调度停止新的自动唤醒；取消当前执行走独立控制路径。先记录取消请求，收到确认后再进入已取消终态；不支持或无法确认时如实展示。等待输入或许可时，响应准确关联原请求。 |
| AC-07 | FR-07 会话与工作区边界 | 不同群、成员及任务工作区不会误用原生会话或代码目录。单个会话同时至多运行一轮；跨成员上下文和代码通过明确的消息、产物及版本交接。 |
| AC-08 | FR-08 结果与版本 | 代码产物关联明确的修改版本或输入快照。测试记录含命令、工作区或环境引用、开始与结束状态、退出码和日志。Agent 的完成报告与实际测试结果分别展示。 |

## 3. 必须覆盖的异常

| 异常 | 验收要求 |
| --- | --- |
| 请求或消息重复投递 | 平台根据请求标识识别重复，返回原任务或执行记录，不重复调度。外部 Agent 是否已接受请求无法确认时，先核对状态，不把重发当成绝对安全的恢复方式。 |
| 成员离线、连接失败或鉴权失败 | 保留用户输入与任务关联，显示可操作的连接状态；不得将连接成功前的任务标为执行成功。 |
| 等待操作许可或用户补充 | 保留底层请求标识和允许的响应选项；同一响应只交付给对应请求，等待状态可被用户看见。 |
| 执行中收到取消 | 控制请求及时送达适配器；已经完成、不可中断和待确认三种结果分开记录。 |
| 事件流意外关闭 | 将执行状态标为待核对，向底层查询或恢复订阅；流关闭本身不构成任务完成证据。 |
| 后台崩溃后恢复 | 恢复任务与原生运行引用，先核对已接受的执行；对于状态不明的写操作，保留待处理状态，不盲目重放。 |
| 能力缺失或版本不兼容 | 缺失、未知和不支持均不能标为已支持。对应操作被明确禁用或说明替代行为，保留原因。 |
| 同伴循环求助或预算耗尽 | 为单个任务设置交流轮数、时间或调用额度等可检查的界限；达到界限停止自动调度并向用户说明。 |

具体超时、并发、预算数值须在测试条件确定后记录，不能在文档阶段虚构性能目标。测试使用独立样例项目，不依赖用户过去项目的代码或数据。

## 4. 测试层次与证据

**模拟测试**验证平台自己的路由、排队、状态转换、去重、超时与故障处理。模拟器可以生成失败或中断事件，但生成的日志和产物必须标记为模拟，不计入真实兼容结论。

**适配器契约测试**验证连接配置、身份映射、事件转换、能力声明和错误语义。每个适配器记录版本、测试条件及未覆盖项；契约通过不代表付费服务、登录流程或真实代码任务已经通过。

**真实集成测试**使用实际 Agent 及其支持的认证方式，在独立项目中执行预先描述的任务。保留适配器和 Agent 版本、输入要求、运行标识、代码快照、命令、日志、退出码及失败原因。涉及费用的规模测试在预算确定后开展。

测试报告使用“通过、失败、阻塞、未运行”区分结果，并附证据位置。文档草案、界面草图和计划中的测试场景均不能记为“已通过”。后续若比较单 Agent 与协作方案，应使用相同任务集及明确的时间、质量和成本口径，记录真实观测值。

## 5. 文档评审清单

- 产品需求是否区分用户已确认的目标与建议的第一版范围？
- 群消息、任务、群成员、连接和原生会话是否具有一致定义？
- 首批接入对象、协议版本及验证优先级是否明确？
- 自动唤醒、同伴求助、取消、断流和恢复的语义是否一致？
- 首版发布范围、演示用例、验收证据及待决策事项是否可追溯？
- 技术栈、操作系统、付费调用预算和并发目标是否仍有未决项？

## 6. 当前执行边界

当前工作只包括阅读、讨论、创建和修改项目文档。可以通过官方资料核实接口事实并修订设计；不创建应用或测试代码、不安装项目依赖、不连接真实 Agent 执行任务，也不因文档列出了里程碑就自动开始开发。

用户明确要求进入实现阶段后，再依据评审后的文档选择下一里程碑。常规文档修订可继续进行，无需为每次文字修改重复申请确认。

## 7. v0.2 可执行验收用例草案

以下用例均为未运行。M1 可用模拟器验证平台行为；真实接入相关结论必须在 M2/M3 重跑并保存证据。

| 用例 | 追踪 | 前置条件与步骤 | 预期结果 |
| --- | --- | --- | --- |
| TC-01 | AC-01/07 | 同类 Agent 创建两个成员，分别发送不同材料 | 成员和会话独立；无上下文串用 |
| TC-02 | AC-02/03 | 使用相同请求 ID 连续派单两次，再用相同 ID 改负载提交 | 前两次返回同一任务且只派发一次；第三次冲突 |
| TC-03 | AC-04 | A 求助 B；B 在 A 当前 Run 结束前回复 | 回复保存；A 释放执行锁后只续接一次 |
| TC-04 | AC-04/06 | A 等待 B，用户取消任务，再送达 B 回复 | 回复保留为历史；不生成新 Run |
| TC-05 | AC-04 | 重复投递回复，再模拟超时后回复 | 重复不唤醒；超时回复标为过期，等待人工继续 |
| TC-06 | AC-04 | A 等待 B，B 请求等待 A；另将预算降到测试阈值 | 等待环被拒绝；预算耗尽停止自动派发并显示原因 |
| TC-07 | AC-05 | 输出期间断开客户端，再按游标连接 | 补齐记录、无重复输出、不重复执行；过期游标走快照恢复 |
| TC-08 | AC-05 | 分别在事务提交前后和外部提交结果未知时终止后台，再重启 | 无半提交；已提交记录恢复；未知副作用不盲目重发 |
| TC-09 | AC-06 | 发取消请求后分别注入成功、已取消、未知结果 | Run 保留真实结果；Task 不再派发；未知不显示已取消 |
| TC-10 | AC-07 | 运行中追加要求，旧版本随后交付；尝试执行中交接 | 新要求下一轮生效；旧结果不满足新版验收；交接被明确阻止 |
| TC-11 | AC-07 | 空闲时交接，随后收到旧负责人交付 | 保留产物但不推进新归属任务状态 |
| TC-12 | AC-08 | 执行测试后修改产物，再提交仅含“通过”的文字报告 | 旧证据绑定旧版本；新版本未验证；文字不升级证据级别 |
| TC-13 | AC-08 | 测试通过但缺少功能条件，用户退回；随后验收完整候选 | 退回进入排队；只有当前要求和版本的用户验收使任务完成 |
| TC-14 | AC-01/07 | 工具请求伪造发送者、跨群 ID、越界文件路径 | 拒绝未授权操作且无副作用；记录脱敏错误 |
| TC-15 | AC-06 | 暂停群调度，再投递普通派单和同伴回复 | 保存记录但不开始新 Run；已有 Run 可继续且取消仍可用 |

每条用例记录：用例 ID、需求编号、日期、执行者、代码版本、适配器/Agent 版本、环境、输入和前置状态、操作、预期、实际结果、日志/产物位置、通过/失败/阻塞/未运行。模拟与真实结果分栏，缺失证据不能填通过。

缺陷记录包含复现步骤、预期与实际、影响范围、关联用例和修复验证。丢记录、越权、重复副作用、错误完成标识属于发布阻断问题；其他缺陷是否延期需记录理由及影响。

各里程碑完成条件：需求与用例关联完整、适用用例执行并附证据、阻断缺陷关闭、能力矩阵和已知限制更新。上述新增建议受对应待决策事项约束，评审改变行为时同步更新用例。
