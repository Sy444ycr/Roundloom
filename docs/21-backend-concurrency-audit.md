# 后端并发与异常状态复查

日期：2026-11-13。检查范围包括 Services 公开入口、Core 调度/控制、存储归属、工作区证据、JSONL 桥接，以及现有适配器、归档、迁移和宿主回归覆盖。以下记录本轮发现和实际修复，不代表所有环境都已验收。

## 修复

| 问题 | 修复后的行为 |
| --- | --- |
| 工作区按登记 ID 加锁，同一目录登记到不同群或登记为父子目录后可以绕过保护 | 依据登记时解析的实际目录判断相同及父子范围，测试、写入、公开快照与产物快照检查互斥。写操作在第一次异步文件操作之前取得锁，覆盖写入、重命名和结果快照；失败后清理临时文件并释放锁 |
| Services 关闭只等待写请求，异步读取或核验尚未完成就可能关闭数据库 | 跟踪全部在途请求，关闭立即拒绝新请求，取消测试后等待全部读写结束；多个关闭调用共享完成过程 |
| Store.put 在 ID 冲突时只替换 JSON，可覆盖不同实体类型或房间的数据 | 仅相同 kind 和 roomId 允许更新；其他碰撞返回 CONFLICT，原记录不变 |
| 同一成员连接未完成就可断开，或断开期间开始新任务 | 连接、认证、断开按成员互斥；冲突控制请求返回 CONFLICT，期间该成员的新派发暂停，其他成员不受影响，结束后正常调度。进行中的控制操作不会被健康轮询覆盖 |
| JSONL 进程退出或协议损坏但未发送终态，被误判为 failed；退出后仍持有子进程句柄 | 没有明确终态的断流、协议错误记为 unknown，任务保持待核对；仅明确终态或可确认的启动失败才记相应结果。进程关闭后移除句柄，dispose 后拒绝新执行 |

工作区互斥约束 Roundloom 服务内的文件操作；不能阻止独立 Agent 进程或用户编辑文件，不能作为系统级文件沙箱或原子快照保证。连接互斥不取消已运行任务，已有运行的停止仍走独立取消路径。JSONL unknown 不会自动重新执行有潜在副作用的任务。

## 验证与追踪

- 新增 concurrency-boundaries.test.ts 六项用例。其中目录别名绕过、写入前异步窗口、关闭读取遗漏、实体 ID 覆盖和连接控制竞态均先在旧实现复现失败，再验证修复。
- cli.test.ts 增加真实 Node 子进程的无终态退出和坏协议场景，验证 unknown、禁止直接 retry 以及句柄释放。
- npm test：60 项通过，0 失败；涵盖既有健康、归档、恢复、迁移、权限、版本证据和异构适配夹具。
- npm run format:check、git diff --check：通过。

本轮未重跑真实模型调用或一小时负载；之前的证据保留原日期与代码阶段。常规 Windows CI 另执行 30 秒 Core 负载和 100 次 MCP 生命周期检查。

## 尚未验收的范围

Electron 窗口来源校验、托盘/退出交互、打包后的原生依赖与安装仍属于桌面阶段；跨平台、真实模型长期并发和更大历史数据集仍需专项验证。厂商不支持查询时，中断执行保持 unknown，不能声称远端已停止。历史归档是同库冷表，不自动删除数据或缩小总文件。最新能力边界同时参考 [健康与归档](20-connection-health-and-history.md)。
