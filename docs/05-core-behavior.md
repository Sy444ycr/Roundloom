# 核心行为与状态规范

版本：v0.2 评审草案｜日期：2026-11-13

本文将 FR-02 至 FR-08 细化为建议的实现契约，未确认的产品选择见 O-06 至 O-09。不是已实现或已批准的功能声明。

## 1. 统一术语

统一使用 `Member` 表示群成员；旧文档的 `GroupMember` 指同一对象。Task 是用户工作目标，Run 是一次执行尝试，Session 是成员原生上下文，三者不能共用状态或 ID。状态枚举以本文为准，界面可使用对应中文名称。

| Task 状态 | 含义 |
| --- | --- |
| queued（排队） | 有待派发工作，尚未执行 |
| running（执行中） | 当前负责人正在推进任务 |
| waiting（等待） | 等待同伴、输入、许可、认证或恢复核对，记录具体原因 |
| review（待验收） | 已提交交付候选，尚无用户验收结论 |
| completed（完成） | 用户对指定要求版本和产物版本确认验收 |
| failed（失败） | 当前尝试无法继续，失败原因已记录 |
| cancelled（已取消） | 已禁止后续调度，相关活跃执行均已确认停止或结束 |

Run 状态为 queued、starting、running、waiting_input、waiting_permission、waiting_auth、succeeded、failed、cancelled、unknown。`cancel_requested` 是独立控制字段，不能覆盖同时到达的真实终态。等待同伴发生在平台层：原 Run 结束，Task 等待，回复通过新 Run 继续。普通问答 Run 成功不生成 Task。

## 2. Task 转换及权限

| 原状态 | 事件与条件 | 目标状态 |
| --- | --- | --- |
| 无 | 用户显式派单，接收成员和要求有效 | queued |
| queued | 负责人 Run 已确认开始 | running |
| queued/running | 出现必要等待项 | waiting |
| waiting | 必要等待项满足、未取消、预算允许 | queued |
| running | 当前负责人提交完整交付候选 | review |
| review | 用户对当前版本验收通过 | completed |
| review | 用户退回并说明缺口 | queued |
| queued/running/waiting | 不可恢复错误且执行状态已核对 | failed |
| 非终态 | 取消条件满足 | cancelled |
| failed/cancelled | 用户明确重试 | queued，建立新尝试并关联旧尝试 |

completed 不自动重开；新增需求创建关联任务。Run 成功本身不代表 Task 完成；普通求助回复也不能将任务置为待验收。未知运行进入 waiting，保留 unknown 原因，不推定失败。终态纠错只能通过带原因的显式核对事件，不能覆盖历史。

暂停群内调度仅阻止新 Run，包括同伴唤醒；不停止现有 Run。取消针对任务传播到该任务派生的排队运行、协作请求和活跃运行。先封锁后续派发，再逐个请求取消；不支持停止或结果未知时，界面显示“取消待确认”。无活跃运行时可直接确认取消。

## 3. 并发与竞态

- 同一原生会话共享一个执行锁；同一任务的状态变更按 taskVersion 乐观并发校验。冲突返回最新版本，不能静默覆盖。
- 取消意图持久化后，迟到回复只入历史，不唤醒任务。正在提交给 Agent 的运行若结果未知，进入核对流程，不能宣称取消完成。
- 取消与成功同时到达：Run 记录实际成功或已取消；已接受的任务取消意图继续阻止派发，Task 可在所有运行结束后取消，已有产物保留。若任务已 completed，取消返回终态冲突。
- 修改要求生成 requirementsVersion。首版建议只在下一轮生效；当前轮结果绑定旧版本，不自动满足新版验收。界面明确“待下一轮生效”。
- 首版交接建议在无活跃运行时进行。用户先暂停或取消当前执行，提供交接说明与版本引用，原子更新负责人及 ownershipVersion。旧负责人迟到结果保留，但无权推进新归属的任务状态。
- 同一回复由 requestId 与 replyId 去重；历史重放只恢复展示，不调用调度器。新执行必须来自持久化且未消费的派发意图。

## 4. 同伴求助与上下文

首版建议每个求助请求只指定一个接收成员、每个任务同时最多一个待答请求，不支持隐式多方汇总。请求含 roomId、taskId、senderMemberId、recipientMemberId、requestId、问题、requirementsVersion、deadline 和 lineageId；发送者由服务绑定。

请求创建与等待登记原子保存。若回复先于发起 Run 结束到达，先缓冲，待会话执行锁释放后续接；不得丢失回复或并发运行。回复必须引用 requestId，重复回复不重复唤醒。超时关闭请求并转为等待用户处理；迟到回复展示为过期，可由用户明确选择重新继续。

同伴请求形成有向等待图；新增请求如导致等待环则拒绝并返回协作错误。每个任务继承同一协作预算，嵌套求助不得重置；达到轮次、时间或调用限制后暂停自动推进，等待用户处理。预算数值见 O-05。

每轮输入记录 contextManifest：当前任务及要求版本、负责人版本、触发消息、相关线程、产物引用、摘要版本。优先保留当前要求和待回答问题，再按相关性和时间选历史；裁剪必须记录遗漏范围，不能静默丢弃当前约束。私有原生会话不跨成员复制。上下文上限待首批适配器实测后确定。

## 5. 验收与版本

首版建议由用户确认完成，Agent 只能提交待验收候选。验收记录包含 actor、时间、requirementsVersion、artifactVersion、逐项条件及结论。测试通过与任务完成分别展示。

代码版本可用 commit 加工作区内容摘要表达；有未提交修改时，必须保存被测文件清单和内容摘要或可恢复快照。测试证据来自受控执行记录或可核查的适配器工具结果；仅文本声明标为未验证。

产物改变后，旧测试仍属于旧版本，新版本显示未验证；要求改变后，旧验收不能覆盖新要求。测试通过但功能条件未满足时仍不得自动完成。
