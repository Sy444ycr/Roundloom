# 首版范围与关键交互

> 2026-11-13 更新：首发形态已确定为桌面应用。本文涉及本地 Web 首发的内容为历史候选，桌面进程、通信和生命周期以[桌面架构选型](09-desktop-architecture.md)为当前推荐；其余业务语义继续有效。

版本：v0.2 评审草案｜日期：2026-11-13

## 1. 建议范围

目标用户为单个开发者，在项目群协调编码 Agent。建议首版发布覆盖 M1—M3，M4 作为开放接入能力的后续验证；这与 O-04 一并待决策，不改变原有验收路线。首版建议包含建群、多实例成员、定向讨论、显式任务、单接收者求助、人工验收、事件恢复和真实产物记录。

首版建议暂不包含多人账户、云端托管、适配器市场、自动合并、任意工作流编排和远程 A2A 的实际实现；保留相应契约边界。是否采用此范围由范围决策确认。

## 2. 界面与操作契约

| 入口 | 必要输入与结果 | 失败与恢复 |
| --- | --- | --- |
| 建群 | 名称、可选项目目录；生成稳定群 ID | 路径不可用时解释原因；咨询群可无目录 |
| 添加成员 | 连接配置、名称；展示能力与连接状态 | 配置保存不等于连接成功；支持编辑后重连 |
| 发言 | 文本、可选结构化接收者、引用 | 无接收者只存记录；发送失败保留草稿，重试使用相同请求 ID |
| 分配任务 | 负责人、目标、验收条件 | 条件可暂缺但明确提示未完善；未连接成员的任务排队并显示阻塞原因 |
| 追加要求 | 新内容及预期版本 | 生成新要求版本；显示下一轮生效，拒绝覆盖并发更新 |
| 求助详情 | 原问题、请求状态、回复和任务链接 | 超时、过期、预算耗尽均有原因及人工继续入口 |
| 交接 | 新负责人、背景、待办、代码版本 | 活跃运行未结束时不提交交接，提示先处理现有执行 |
| 产物验收 | 查看版本、差异、证据；通过或退回 | 版本变化要求刷新；退回必须给出缺口 |
| 暂停/取消 | 区分群调度暂停与任务取消 | 展示请求中、不支持、未知和已确认结果 |

群聊、任务面板和执行详情引用同一对象，不能各自维护独立状态。任务卡展示负责人、当前状态、等待原因、要求版本和最近产物版本。成员名称相同时用短 ID 区分。

## 3. 完整演示场景

使用独立样例仓库，用户向 A 分配 CSV 导出任务，验收条件包含空值、转义和测试记录。A 向 B 询问字段约定，结束本轮；B 回复后 A 续接并提交代码。用户查看被测版本与证据后验收。再以同一任务类型演示取消期间迟到回复，以及网页断线后的历史补齐。

演示必须标明模拟成员或真实成员；真实接入对象尚未确定。不得以样例文字代替真实调用。

## 4. 可用性验收

核心操作支持键盘访问；加载、空列表、离线和错误均有可辨认状态。发送中阻止重复提交但允许安全重试。长日志按需展开，错误信息可复制，颜色不是唯一状态提示。实时新增内容不强制打断用户阅读历史。
