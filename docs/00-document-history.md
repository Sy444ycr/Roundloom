## 后端快速开始

要求 Node.js 24+。执行 `npm ci` 后，使用 `npm test` 编译并运行集成测试，`npm run demo` 演示两个模拟成员的协作。`npm run build` 后执行 `npm start` 启动持久化 Core（JSONL 调试入口，数据默认保存到 `.roundloom`）。

已实现任务与消息、SQLite 持久化、调度、取消、求助、版本化产物、人工验收和事件订阅。提供 mock 及 Roundloom JSONL CLI 桥接；没有声称任何商业 Agent 已验证兼容。现已补齐工作区、Git worktree、真实测试证据、审批、备份恢复及 ACP 适配器，并完成 OpenCode 最小真实问答联调。Claude Code/Codex 专用路径和桌面 UI 尚未验证。详见[后端扩展交付记录](14-backend-delivery.md)。

Roundloom 是一个以项目群聊为主界面的多 Agent 协作工具。用户可以添加真实的 Agent 成员，在群里讨论、分配任务、补充要求和检查结果；Agent 可以在授权的群聊范围内向同伴提问、交接工作，并提交代码修改与实际测试记录。

接入能力采用开放的适配器契约。Claude Code、Codex、dsh 是需求讨论中举出的例子；产品面向不同协议、不同厂商以及自定义 Agent，允许同类 Agent 以多个独立成员实例参与协作。

本套文档用于先明确产品边界、运行语义和验收依据，再安排实施。当前用户要求只开展文档工作。文档中的功能和验收条件描述拟实现的系统，不表示相关功能已经开发或测试通过。

## 如何放入项目

将本目录的 README.md 与 docs 目录放入项目根目录，保留相对链接。随后在 Codex 中逐项审阅和修订文档。当前阶段可进行需求澄清、规范补充、文档一致性检查和方案比较；进入应用开发阶段以用户后续明确指令为准。

无需为每个常规文档修改增加确认流程。对范围或方案的重大调整，记录到决策清单；已认可的方向持续有效。

## 文档约定

- **已确认方向**来自当前对话明确的用户要求。

- FR 编号用于追踪功能需求，AC 编号用于追踪验收场景。补充需求时保留已引用编号。

- 文档中的示例任务只用于说明协作流程，不限定产品只能处理某一类业务。
