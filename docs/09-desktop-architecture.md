# 桌面架构选型

日期：2026-11-13｜状态：架构基线已确认（C-09/C-10/C-11）；具体工具与版本待细化

## 1. 决策依据

用户明确选择桌面应用，具有 React 开发经验，并要求开放接入主流 Agent。用户已确认 Electron（C-10）。React 界面、独立 Core 与开放适配器架构已确认（C-11）；TypeScript 为开发语言建议，SQLite 为本地存储建议，具体工具和依赖版本继续细化。本轮不开始应用开发。

本文件取代旧草案中的本地 Web 首发建议；业务模型、状态机、事件恢复、验收证据等语义继续有效。

## 2. 桌面框架比较

| 方案 | 与项目的契合点 | 代价 | 结论 |
| --- | --- | --- | --- |
| Electron | React 界面与 Node.js 进程能力可采用同一语言；可用 utility process 承载协作内核 | 打包体积、运行内存与框架安全更新需要管理 | 已选择，见 C-10 |
| Tauri | React 界面可复用；可通过外部进程承载 Agent 和 Node 服务 | 增加 Rust 宿主或 Node sidecar 的构建、跨架构分发和通信维护 | 本轮未选择，保留比较依据 |

依据：Electron [进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)；Tauri [外部二进制](https://v2.tauri.app/develop/sidecar/)及 [Node sidecar](https://v2.tauri.app/learn/sidecar-nodejs/)。上述推荐是基于项目与开发经验的判断，不是两种框架的性能实测结论。

## 3. 推荐进程结构

React Renderer → Preload 的受限 API → Electron Main → Core utility process → Agent 进程或远程连接。

- Renderer：群聊、成员、任务、执行详情；不直接访问数据库、凭据或 shell。
- Preload：按操作暴露窄接口，不暴露通用 IPC、文件读写或执行命令能力。
- Main：窗口、托盘、系统对话框、应用生命周期及 IPC 身份校验；不承载长任务。
- Core：协作内核、调度器、适配器管理、事件持久化和工作区管理；拥有数据库写入。
- Agent：通过结构化协议连接，独立记录会话、运行和能力。独立进程不等同于安全沙箱。

Renderer 启用 contextIsolation 和 sandbox，关闭 nodeIntegration；校验 IPC 发送者和负载，不渲染可执行的 Agent HTML，不将远程页面放入特权窗口。参见 [Electron 上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation/)。

业务模块维持模块化单体。进程边界用于界面响应与故障隔离，不引入微服务部署。

## 4. 通信、存储与生命周期

桌面内部采用有类型的 IPC 命令与事件订阅；不再将 Fastify、HTTP 和 SSE 作为界面通信的首版必选项。命令仍含请求 ID、对象版本；事件仍含持久化序号，窗口刷新或重建后按游标补齐。IPC 并不提供持久化保证。

推荐 SQLite 保存当前状态、追加事件日志和事务内派发记录；大日志与产物存文件系统并记录引用及摘要。数据库存于应用用户数据目录，项目 worktree 属于独立工作区。初始化、迁移、备份和异常恢复需在打包应用中验证。

推荐关闭窗口时进入托盘，Core 继续运行；显式退出时停止新派发并处理活跃任务。默认不承诺完整退出后继续执行。无法停止的远端或原生运行保存恢复引用并明确提示。Core 崩溃时 Main 展示断开状态，重建 Core 后核对运行，不能直接重发任务。具体关闭和退出交互属于待评审建议。

## 5. 开放 Agent 接入

扩展分为两级：协议相同的 Agent 通过连接配置加入；协议不同的 Agent 通过新适配器加入。核心不得出现按品牌分支的任务逻辑。

适配器清单至少包括 adapterId、契约版本、配置 schema、支持的传输、认证方式、能力探测及实现版本。操作包括探测、连接、建立会话、开始运行、回答交互、取消、查询/恢复、获取产物和断开。适配器必须输出统一事件并保留原生引用。

接入路径包括 ACP、原生 SDK、结构化 CLI 和未来的 A2A；MCP 或原生工具回调负责群内读写与求助。模型 API 本身不构成具备文件、命令和协作工具的完整 Agent；若支持模型直连，需另外实现并声明平台运行时。

能力按输入输出、流式事件、会话续接、取消、审批、工具绑定、工作区、产物和用量分别记录 supported/unsupported/unknown。普通聊天、编码执行和主动同伴协作是不同能力等级；缺少某项能力不必拒绝整个成员，但相应操作必须禁用或明确降级。

“覆盖主流 Agent”是兼容性建设目标，不能承诺无接口的封闭产品直接使用。首批真实对象仍需选定并实测；标准协议一致也不能替代版本与能力验证。首版适配器采用随应用发布或显式配置的可信实现，插件市场、热加载与第三方代码隔离另行设计。

## 6. 进入实现前的验证项

进入实现阶段后，先验证打包版 Agent 启动、路径与环境继承、中文/空格路径、取消进程树、SQLite 驱动兼容、窗口重建和 Core 崩溃恢复。Windows 原生与 WSL 运行环境必须分别声明；桌面界面跨平台不代表所有 Agent 跨平台兼容。具体首发系统仍待确定。
