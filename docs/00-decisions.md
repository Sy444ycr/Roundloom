## 范围解释

“支持主流 Agent”表示建立持续扩展和验证的兼容体系。支持标准协议的 Agent 可以通过对应通用适配器接入；其他拥有可用程序化接口的 Agent 通过独立适配器接入。缺少可用接口的产品需要记录为待支持，不用名称占位冒充已集成。

“互相交流”至少包含针对同一任务的提问、回答和交接。主动向同伴发起消息需要群聊工具绑定或可用回调，不能从“支持接受提示”直接推定该能力。

“任务完成”需要区分 Agent 的自述、一次运行的终态与验收结论。测试报告只有在实际执行后才能记录通过或失败。

## C-11 架构基线确认

- 日期：2026-11-13；状态：已确认；依据：用户明确“就按这个架构来”。
- 选择：React 界面通过受限 Preload/IPC 访问 Electron Main，Main 管理独立 Core utility process；Core 负责协作、调度、存储与适配器，Agent 通过独立进程或远端连接执行。
- 约束：界面无直接命令执行与数据库权限；Core 为数据库所有者；持久化派发、事件补齐和未知运行核对继续有效。采用 10 文档的模块目录与生命周期设计，以及 11 文档的统一操作、能力声明和群聊工具身份边界。
- 理由：匹配桌面交互、本地 Agent 执行及开放接入目标，使界面、协作规则和厂商协议分别维护。
- 影响：FR-01 至 FR-08；以 09—11 文档作为后续实施架构基线。旧文档中的“推荐”不再意味着需要重新确认上述架构方向。
- 仍待细化：存储具体选型及驱动、构建打包工具、依赖版本、首发操作系统、首批真实 Agent、运行预算与量化阈值。SQLite 仍为存储首选建议；其他产品范围事项保持原状态。
- 阶段：确认架构，不等同于本轮开始编码；下一步收敛实施工具与 M1 计划。
