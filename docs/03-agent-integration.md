# Roundloom Agent 接入规范

**版本：v0.1｜状态：待评审草案｜日期：2026-11-13**

本页定义拟议的接入边界与连接器契约。文中“应”“不得”为建议约束，尚不代表范围已批准或功能已实现。现有界面草图均未连接真实 Agent，示例消息、运行状态与日志不构成兼容性证据。

## 1. 接入边界

Roundloom 拟统一群聊侧的会话、运行和事件；推理、编码及工具执行仍由所接入 Agent 完成。核心按插件注册和能力工作，不枚举厂商，不承诺任意 Agent 自动获得全部功能。

| 接入层 | 拟议用途 | 边界 |
| --- | --- | --- |
| ACP | 本地 coding agent 的接入主线 | 连接实现相应版本的 Agent 或桥接器，逐项核实能力 |
| 原生 SDK／结构化 CLI 协议 | 补充 ACP 未覆盖的 Agent 或功能 | 使用有文档的接口；自行适配不得标成官方实现 |
| A2A | 独立远程 Agent 的扩展路径 | 接收消息、任务状态和产物，不假定可控制远端内部工具 |
| MCP | 提供共享群聊工具 | 不负责启动 Agent、管理完整运行生命周期或后台唤醒 |

这里的 ACP 指 **Agent Client Protocol**。官方将其定位为客户端与 coding agent 的交互协议，将 MCP 定位为工具与数据接入，将 A2A 定位为向独立 Agent 委派任务。[协议关系说明](https://agentclientprotocol.com/get-started/related-protocols)

接入记录应固定协议与实现版本。本草案参考 ACP v1 会话流程；核读时官网将 v1 标为 Latest、v2 标为 Draft，不能混用两版方法。[ACP v1 概览](https://agentclientprotocol.com/protocol/v1/overview)

## 2. 对象与原生映射

| 对象 | 最少记录字段 | 职责 |
| --- | --- | --- |
| AdapterPlugin | 插件 ID、插件版本、配置规范、协议范围 | 实现某种协议或 SDK 的转换；不保存群成员身份 |
| Connection | 连接 ID、插件 ID、启动配置或端点、凭据引用、协商版本 | 一个具体连接配置及其运行连接；保存鉴权与能力快照 |
| GroupMember | 成员 ID、房间 ID、连接 ID、显示名、角色、可选工作区引用 | 群中的成员实例；同一连接配置可创建多个成员 |
| Session | 平台会话 ID、成员 ID、原生引用、恢复方式 | 保存该成员在房间内的上下文关联 |
| Run | 运行 ID、会话 ID、可选任务 ID、触发消息 ID、状态、原生引用 | 跟踪一次执行及其结果；普通回复可不关联任务 |

成员默认使用独立会话，显示名不能作为身份标识。同一连接能否承载多个独立会话按适配器能力判断，不支持时建立独立连接实例。复用同一个原生会话须显式登记，其所有入口共同遵守单活跃 turn 约束。原生引用包含连接作用域、资源类型与原生 ID，禁止跨连接直接复用。

平台任务、Run 与原生任务不要求一一对应。一次平台任务可以有多轮运行；A2A 的 context 可关联多个原生 task，追加输入也可能继续同一个 task。映射表应保留这些关联，而不是伪造一个原生 session ID。[A2A 核心概念](https://a2a-protocol.org/latest/topics/key-concepts/)

## 3. 建立连接与能力核实

建议流程为：加载插件并校验配置 → 协商版本 → 按官方流程完成必要鉴权 → 核实能力 → 创建成员会话 → 保存快照与证据。鉴权可能改变可用能力；后续配置或账户变化应使旧快照失效。

| 能力项 | 应说明的差异 |
| --- | --- |
| 输入与输出 | 内容类型；流式更新或结果返回；错误表示 |
| 会话连续性 | 原生恢复、历史读取／重放、重新启动分别声明 |
| 运行控制 | 能否请求取消；如何确认停止；是否可查询运行状态 |
| 人机交互 | 鉴权、输入补充、权限审批各自的官方入口 |
| 工具绑定 | MCP 或原生工具／回调；仅建会话时配置或支持动态变更 |
| 工作区与产物 | 本地、远程或无工作区；产物获取方式 |
| 用量 | 可报告的 token、费用或时长；缺失时保持未知 |

每项记录 `supported`、`unsupported` 或 `unknown`，并区分“文档声明”“握手声明”“实际验证”。未声明不等于支持；未知能力不得显示为可用。必要能力缺失时应指出限制；改为新会话、轮询或人工转发等降级应透明展示。

ACP v1 要求初始化时协商能力，加载历史会话受 `loadSession` 能力约束，不能无条件调用恢复方法。[会话建立与加载](https://agentclientprotocol.com/protocol/v1/session-setup)

## 4. 插件操作与事件契约

以下是语义契约，不规定实现语言或原生方法名。

| 操作 | 输入要点 | 返回与边界 |
| --- | --- | --- |
| 连接／探测 | 连接配置、凭据引用 | 协商结果、能力或待鉴权状态 |
| 建立会话 | 成员、可选工作区与工具绑定 | 平台会话和可获得的原生引用 |
| 开始运行 | 会话、消息、运行 ID、请求 ID、可选任务 ID | 已接受或失败；已接受不表示完成 |
| 回答交互 | 交互请求 ID、被允许的选择或输入 | 官方流程接受结果；不能伪造授权 |
| 请求取消 | 运行 ID | 已请求、不可取消、不支持或失败 |
| 恢复／查询 | 已登记的会话或运行引用 | 当前状态及恢复结果；不支持时明确返回 |
| 获取产物／断开 | 产物引用或连接引用 | 获取结果／连接关闭；关闭不等于远端任务停止 |

| 事件 | 必须表达的信息 |
| --- | --- |
| 消息更新 | 内容、来源运行、是否增量；不默认等同于群内发送指令 |
| 运行状态 | 原生状态及归一状态；是否为已确认终态 |
| 交互请求 | 鉴权、补充输入或审批类型，请求 ID、选项、有效期 |
| 产物更新 | 产物 ID、来源、版本、可获取状态 |
| 用量／错误 | 实际可观察的用量；错误类别、重试条件与原因 |

事件关联连接、成员、会话和运行；暂不适用的字段可空。核心追加事件序号并持久化，原生事件 ID 或游标可另存用于去重。连接器只转换已观察的信息，不用“流结束”“进程失联”推断任务成功。

## 5. 连续性、取消与审批

**原生恢复**是底层明确支持的会话续接；**历史重放**只是重新展示或提供既有消息，不代表恢复内部状态；**重新启动**创建新的执行上下文，应记录新旧关联。重放不能自动重复有副作用的操作，也不能继承已经过期的批准。

`cancel_requested` 与 `cancelled` 分开。取消请求被接受后，仍需原生终态或可验证的本地停止结果；无法确认时保留待确认状态。终止进程也不等于撤销已经写入的文件。A2A 规范说明取消可能不成功。[A2A 规范中的取消操作](https://a2a-protocol.org/latest/specification/)

认证和工具权限沿用官方流程。凭据只保留引用，不进入群消息、模型上下文或普通事件日志。审批绑定请求、运行及目标操作；群里一句“同意”不能由连接器解释为任意原生操作的授权。

## 6. 成员互相通信与身份边界

主动 peer messaging 需要可验证的工具绑定或官方回调。共享工具可提供读群消息、发送消息、读取任务和报告任务；MCP 只是其中一种承载方式。仅支持文本输入输出的连接器，可以收任务并回复，不因此自动具备主动调用其他成员的能力。

消息发送者由连接器运行身份绑定，不能由模型随意填写。接收者使用结构化成员 ID；文本中的名字或 `@` 不应越过路由校验。跨会话请求关联房间、任务和 request ID，不透传原生凭据、会话授权或完整私有上下文。

请求同伴后结束本轮并登记等待，收到关联回复后再开启下一轮；等待不占住运行槽。恢复后的重放事件不得再次触发请求。原生 session／task 的归属始终保留，跨成员协作不能变成跨成员冒用。

## 7. 工作区与产物

工作区引用是可选项。本地可指向已分配目录或 worktree；远程可引用其服务支持的工作区；纯咨询成员可无工作区。worktree 仅隔离代码修改，不能表述为执行权限隔离。远端返回的路径也不能直接当成本地文件路径。

产物至少记录名称、类型、来源运行、获取引用及状态；可获得时补充大小、摘要和版本。获取可能由适配器携带所需认证完成，引用存在不等于下载成功。补丁另外绑定仓库、基准 revision 与目标工作区；接收或下载产物不等于批准合并。A2A 支持以消息部分与 Artifact 表达文本、文件引用及结构化结果。[消息与产物概念](https://a2a-protocol.org/latest/topics/key-concepts/)

## 8. 兼容矩阵与待评审项

官方生态清单可用于发现候选，但不能代替本项目验证；清单同时包含原生实现与经适配器接入的实现。[ACP Agents 清单](https://agentclientprotocol.com/get-started/agents)

| 候选连接器 | 验证级别 | 原生／桥接路径 | 锁定版本 | 能力结果 | 测试证据 |
| --- | --- | --- | --- | --- | --- |
| ACP 通用连接器 | 未验证 | 按具体 Agent 登记 | 待定 | 全部待核实 | 无 |
| 原生 SDK／结构化 CLI 连接器 | 未验证 | 官方入口及自有适配层待登记 | 待定 | 全部待核实 | 无 |
| A2A 远程连接器 | 未验证 | 远程端点或桥接服务待登记 | 待定 | 全部待核实 | 无 |

验证级别建议依次为：未验证、文档对照、握手通过、核心流程实测、异常流程实测。版本记录覆盖 Agent／CLI、SDK、协议与插件；证据包含日期、环境、用例、日志和失败项。通过一项用例不得概括成“全功能支持”。

待评审：首批实际接入对象与固定版本、必需能力集合、远程扩展是否进入首版、认证交互与工作区授权边界。确定后再制定实现和测试计划；本草案不授权安装连接器或启动真实 Agent。
